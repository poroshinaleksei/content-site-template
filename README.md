# Website template

AI first starter template for small informational websites.

The scaffold is built with Next.js App Router, React, TypeScript, Tailwind CSS,
shadcn/ui style primitives, local typed MDX content, config driven pages and reusable
sections.

This repository is meant to work as a scaffold source for Codex and similar tools.
The intended flow is to create a new local project from this repository first, run setup,
start the baseline site, and only then continue with deeper customization.

## Quick start

```bash
corepack enable
pnpm install
pnpm dev
```

Open `http://localhost:3000`.

## Using this template with Codex

When using Codex, the expected flow is:

1. Use this repository as the scaffold source.
2. Create a new local project from it.
3. Run `pnpm install`.
4. Run `pnpm setup`.
5. Run `pnpm dev`.
6. Only after the baseline site is running, continue with client specific customization.

The setup flow also asks for the preferred user communication language and documentation language for the generated project.
Commit messages, code comments, and source code stay in English.

Short Codex prompt example:

```text
Use this repository as the scaffold source. Create a new local project first, run setup, get the baseline site running, then customize it through AGENTS.md, brief.md, config/, and content/.
```

## Main commands

- `pnpm dev`: run the local development server.
- `pnpm build`: create a production build.
- `pnpm start`: run the production server after build.
- `pnpm lint`: run ESLint.
- `pnpm typecheck`: run TypeScript checks.
- `pnpm format`: check formatting.
- `pnpm check`: run lint, typecheck and build.
- `pnpm new:article "Article title"`: create a draft MDX article in the default locale.
- `pnpm new:article -- --locale en "Article title"`: create a draft English article.
- `pnpm setup`: initialize config and `brief.md` for a new client project.

## Routes

- `/`: Norwegian home page from config and active preset.
- `/about`: Norwegian about page.
- `/articles`: Norwegian article list from `content/articles/nb/*.mdx`.
- `/articles/[slug]`: Norwegian article detail page.
- `/contact`: Norwegian contact page with structured links and disabled form delivery.
- `/en`: English home page.
- `/en/about`: English about page.
- `/en/articles`: English article list from `content/articles/en/*.mdx`.
- `/en/articles/[slug]`: English article detail page.
- `/en/contact`: English contact page.
- `/sitemap.xml`: generated sitemap.
- `/robots.txt`: generated robots file.

## Customization surfaces

- `brief.md`: generated by `pnpm setup`, used as the primary client brief.
- `config/site.ts`: site name, owner, URL, locales, site preset and default SEO.
- `config/i18n.ts`: locale URL prefixes.
- `config/navigation.ts`: header and footer navigation.
- `config/theme.ts`: active theme preset and visual tokens.
- `config/presets.ts`: site type presets and preset page overrides.
- `config/links.ts`: contact destinations, social profiles and external links.
- `config/features.ts`: optional feature selection.
- `config/pages/*.ts`: page composition and section content.
- `content/articles/<locale>/*.mdx`: local article content.
- `components/sections/`: reusable section implementations.

Keep client specific data in config and content first. Edit components when the requested
layout or behavior cannot be expressed through the existing section contracts.

## Stack

- Next.js 16 App Router
- React 19
- TypeScript
- Tailwind CSS 4
- shadcn/ui compatible local primitives
- `gray-matter` and `zod` for typed MDX frontmatter
- `next-mdx-remote` for MDX rendering
- `@next/third-parties/google` for optional GA4
